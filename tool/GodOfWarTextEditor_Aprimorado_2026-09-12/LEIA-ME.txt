God of War Text Editor — Windows x64

VERSÃO APRIMORADA PELO FLUXO DO ELF

O editor trabalha diretamente sobre recursos existentes no WAD. Ele não
precisa exportar o texto para editar e não reserializa recursos binários que
não foram alterados.

USO RÁPIDO
1. Abra GodOfWarTextEditor.exe.
2. Clique em Abrir WAD e selecione R_PERM.WAD ou outro WAD compatível.
3. Escolha o recurso na lista. O editor reconhece msgs_*.txt e também
   MSGS_TXT, usado pelo runtime Flash do demo GoW2.
4. Escolha a codificação correta. Windows-1252 é o padrão do browser e do
   R_PERM.WAD fornecido. Para fontes/runtime japoneses há Shift-JIS/CP932.
5. Selecione uma mensagem por ID ou use a busca por ID/conteúdo.
6. Edite o texto à direita. Enter cria LF real. Backspace no começo da linha
   remove o LF. Clique em Aplicar texto.
7. Use Diagnóstico para verificar IDs duplicados/desordenados, dicas H/T,
   páginas separadas por --, linhas acima do limite do DoMsgPage, macros e
   linhas vazias descartadas pelo parser nativo.
8. Salve com Salvar WAD como... O WAD original não é sobrescrito por padrão.

ATALHOS
- Ctrl+O: abrir WAD
- Ctrl+S: sempre abrir "Salvar como..." para escolher o destino e criar backups
- Ctrl+Z: desfazer a última edição feita no campo da mensagem
- Ctrl+F: focar a busca

Ctrl+Z opera sobre o histórico do campo de texto selecionado. Ao trocar de
mensagem, o histórico é reiniciado para não desfazer acidentalmente o conteúdo
de outra mensagem.

RECURSOS RUNTIME MSGS
O ELF do demo mostra que o runtime procura os objetos lógicos:

- MSGS_COUNT: contador binário de mensagens;
- MSGS_LINES: contador binário de linhas;
- MSGS_TXT: payload TXT com marcadores *ID*, *ID*H ou *ID*T.

O loader IFF acrescenta um prefixo de tamanho ao MSGS_TXT apenas em memória.
O editor mantém o payload textual cru no WAD e não grava esse prefixo artificial.
MSGS_COUNT/MSGS_LINES não aparecem como recursos editáveis de texto.

O parser nativo ignora linhas vazias, ignora linhas iniciadas por //, aceita
marcadores terminados em *, *H ou *T e usa -- como separador de páginas. O
DoMsgPage observado no demo aceita no máximo três linhas por página. A edição
preserva linhas vazias e comentários para manter o arquivo original; o botão
Diagnóstico mostra o que o runtime efetivamente descartará.

DICAS H/T
- *123*H identifica o código de dica nativo 1.
- *123*T identifica o código de dica nativo 2.
- *123* não possui código de dica.

ENCODING
- Windows-1252: padrão recomendado para R_PERM.WAD e god_of_war_browser.
- ISO-8859-1, Windows-1251, UTF-8, UTF-8 com BOM.
- Shift-JIS/CP932: opção para conteúdo compatível com o modo de dois bytes
  indicado pela função Decode do runtime.

DICIONÁRIO DE ACENTOS DO GOW2
Com Windows-1252 selecionado, a interface trabalha visualmente com Unicode:
se você digitar `Fácil`, `Difícil`, `Titã`, `ação`, `coração` ou `Órgão`, o
editor grava no TXT os bytes CP1252 correspondentes (`á=E1`, `ã=E3`, `ç=E7`,
`é=E9`, `í=ED`, `ó=F3`, `ô=F4`, `õ=F5`, `ú=FA`, além dos maiúsculos). O
mapeamento fica explícito no dicionário `GOW2_CP1252_DICTIONARY` da fonte e é
usado tanto para a conversão ao salvar quanto para a visualização ao carregar.
Não é necessário digitar códigos hexadecimais nem UTF-8 manualmente.

O editor verifica erros de conversão antes de salvar. Se o glyph não existir
na fonte do filme, trocar apenas o encoding do TXT não fará o caractere surgir
no jogo: o F_Font precisa possuir o código no codeArray.

QUEBRA DE LINHA: LF REAL VERSUS \\n LITERAL
- LF real é o byte 0x0A e aparece como uma nova linha.
- Barra invertida + n são dois bytes literais e não quebram linha sozinhos.
- A caixa “interpretar \\n” converte a notação literal ao aplicar o texto.
  Fica desligada por padrão para não modificar dados existentes sem aviso.
- Um NUL final existente no recurso é detectado e preservado.

PRÉVIA
A prévia CRT possui dois perfis:

- Automático: GoW1 usa os dados observados no FLP_HUD (5 linhas); MSGS_TXT
  e GoW2 usam o perfil Runtime Flash (3 linhas).
- GoW1 FLP_HUD: X=-397.5, Y final=14.25, entrelinha=37.5 e tela lógica 800×448.
- Runtime Flash: três linhas são o limite confirmado no DoMsgPage, mas o ELF
  não fornece neste export uma matriz única de posição equivalente ao FLP_HUD.
  X/Y/entrelinha são, portanto, parâmetros aproximados de visualização.

A prévia não modifica o FLP. No runtime, posição e aparência são determinadas
por F_EditText, F_Font, F_Matrix, F_Cxform, sprites e frames do filme.

PRESERVAÇÃO DO WAD
- Header físico de 0x20 bytes, campos little-endian e alinhamento de 0x10.
- Tags não editadas são emitidas byte a byte, inclusive padding não nulo.
- Tags editadas mantêm tag, flags, nome e conteúdo; o novo padding segue a
  regra do formato.
- Recursos desconhecidos e corpos não textuais não são reinterpretados.
- A gravação usa arquivo temporário e troca atômica. Se você escolher o mesmo
  caminho do original, um backup .bak é criado antes da substituição.

DIAGNÓSTICO DO ELF E DOS ACENTOS PT-BR
As análises detalhadas estão em:
- ANALISE_GOW2_RUNTIME_FLASH_TXT.md
- ANALISE_PERM.md
- ANALISE_R_PERM_PTBR_ACENTOS.md

O WAD traduzido PT-BR anexado confirma o método: msgs_en.txt em Windows-1252,
fonte FLP_HUD com 24 glyphs CP1252 extras e os recursos GFX_PTBR_ACC,
PAL_PTBR_ACC e TXR_PTBR_ACC. Não basta salvar o TXT como UTF-8; a fonte e os
bytes do texto precisam corresponder.

Ela documenta ReadMsgText, ParseMsgFile, FindMsg, DoMsg, DoMsgPage,
FlashInterface::GetVariable, F_EditText, F_Font, Decode, TextRender,
EditTextBuild e a diferença entre o FLP do browser e o F_Movie Flash do demo.

LIMITAÇÃO CONSCIENTE
Os bytes das constantes DAT_002edcb8, DAT_002edcc0, DAT_002e97c8 e
DAT_002e9790 não aparecem no export C do Ghidra. O editor segue o comportamento
confirmado e sinaliza hipóteses/limites no diagnóstico, sem inventar esses
bytes.

EXECUTÁVEL .EXE (2026-09-13)
- A pasta agora inclui GodOfWarTextEditor.exe: launcher Windows 64-bit com o
  ícone ômega incorporado no próprio arquivo (aparece no Explorer, na barra
  de título, na barra de tarefas e nos atalhos).
- Duplo clique no EXE abre a tool: ele usa o Python portátil da pasta app\
  (pacote .ZIP completo — nada precisa estar instalado) ou, se a pasta app
  não estiver presente, procura um pythonw.exe do sistema (nesse caso é
  necessário: pip install PySide6).
- O EXE sempre executa o gow_text_editor.py desta pasta: para alterar ou
  atualizar a tool, edite o .py — não é preciso recompilar nada.
- Sem console e não assinado: o SmartScreen pode pedir "Mais informações >
  Executar assim mesmo" na primeira execução.
- Se um dia o programa não abrir, procure o arquivo erro_python.log na pasta
  da tool: o EXE grava nele qualquer erro do Python para diagnóstico.
- Distribuição recomendada: o pacote GodOfWarTextEditor_Aprimorado_2026-09-12_EXE.zip,
  que já traz a pasta app\ completa (Python 3.13.1 + PySide6 6.11.2 Essentials;
  ~65 MB extraídos, ~33 MB compactados).

RÓTULOS DESENHADOS DO FILME — FLP (2026-09-16)
- Menu Ferramentas > "Rótulos desenhados do filme (FLP)...":
  edita textos que NÃO passam pelo MSGS porque são DESENHOS dentro do
  filme Flash (StaticLabels) — exemplo: "Total PlayTime" na tela STATUS
  do R_PERMA (FLP_HUDA).
- A lista mostra os rótulos decodificados (usando a fonte do próprio
  FLP) e permite trocar o texto. O avanço das letras é herdado do
  rótulo original (com fallback largura_natural x fator_medido), e o
  cabeçalho do bloco é preservado byte a byte.
- Rótulos com vários blocos de desenho, sem fonte resolvida ou com
  glifos fora do mapa aparecem como [somente leitura].
- Caracteres sem glifo na fonte são recusados com aviso (a lista de
  caracteres disponíveis é a do charArray da fonte do rótulo).
- A edição é em memória: use Salvar WAD como... para gravar. O botão
  "Restaurar original" volta o FLP ao estado de quando o diálogo foi
  aberto.
